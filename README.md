# InfoSecContour — контур информационной безопасности

Консольное приложение на C# / .NET 10. Проект демонстрирует четыре базовых механизма защиты информации:

1. **BCrypt** — хеширование и проверка паролей.
2. **DPAPI** — шифрование и расшифровка локального секрета средствами Windows.
3. **X.509** — загрузка сертификата и построение цепочки доверия через `X509Chain`.
4. **RBAC** — разграничение функций по ролям пользователей.

## Требования

- .NET 10 SDK.
- Доступ к NuGet для первого восстановления пакетов.
- Windows 10/11 для полноценной работы пункта DPAPI.
- Для проверки отзыва сертификата через интернет — доступ к серверам OCSP/CRL соответствующего удостоверяющего центра.

Пакеты NuGet:

- `BCrypt.Net-Next` 4.2.0
- `System.Security.Cryptography.ProtectedData` 10.0.14

## Запуск

Откройте терминал в каталоге `InfoSecContour` и выполните:

```bash
dotnet restore
dotnet build
dotnet run
```

При первом запуске программа предложит создать первого администратора. Имя пользователя и пароль вводятся вручную. Пароль сохраняется в файле пользователей только в виде BCrypt-хеша.

При следующих запусках войдите под созданной учетной записью.

## Роли и права доступа

| Функция | Administrator | SecurityOperator | Auditor |
|---|:---:|:---:|:---:|
| Создать BCrypt-хеш | Да | Да | Нет |
| Проверить пароль по хешу | Да | Да | Нет |
| Зашифровать секрет DPAPI | Да | Да | Нет |
| Расшифровать секрет DPAPI | Да | Да | Нет |
| Проверить X.509 | Да | Да | Да |
| Управлять пользователями | Да | Нет | Нет |
| Смотреть журнал действий | Да | Да | Да |

Роль назначается администратором при создании пользователя. Пользователь без соответствующего разрешения не может выполнить пункт меню: проверка разрешения также выполняется в обработчике действия.

## Данные приложения

Файлы приложения сохраняются в каталоге пользователя:

`<LocalApplicationData>/InfoSecContour/`

В нем находятся:

- `users.json` — имена пользователей, роли и BCrypt-хеши паролей;
- `audit.log` — журнал действий (без исходных паролей и секретов);
- `protected-secret.bin` — зашифрованный DPAPI-секрет.

Чтобы сбросить настройку и пройти создание администратора заново, закройте приложение и удалите каталог `InfoSecContour`. Перед удалением сохраните нужные данные.

## Как проверить функции

### 1. BCrypt

1. Войдите как администратор или SecurityOperator.
2. Выберите `1` и введите тестовый пароль.
3. Скопируйте выведенный BCrypt-хеш.
4. Выберите `2`, введите тот же пароль и вставьте хеш.
5. Программа сообщит, совпали ли пароль и хеш.

BCrypt сам генерирует соль и включает ее в строку хеша. Хеширование не является обратимым шифрованием: исходный пароль из хеша не восстанавливается.

### 2. DPAPI

Эта функция работает только в Windows. Войдите под Windows-учетной записью, под которой выполняется программа.

1. Выберите `3`, введите тестовую строку.
2. Программа сохранит зашифрованные байты в `protected-secret.bin`.
3. Выберите `4`, чтобы расшифровать строку.

Используется `DataProtectionScope.CurrentUser`. Поэтому файл можно расшифровать в контексте того же пользователя Windows. Другой профиль пользователя не должен иметь возможность расшифровать эти данные. На macOS и Linux пункт сообщает, что DPAPI не поддерживается, остальные функции продолжают работать.

### 3. Проверка X.509

Программа принимает обычные сертификаты `.cer`, `.crt`, `.pem` (DER/PEM) и контейнеры `.pfx` / `.p12`. Для PFX программа запросит пароль.

1. Выберите `5`.
2. Введите путь к файлу сертификата.
3. При необходимости введите пароль PFX/P12.
4. Выберите, проверять ли отзыв сертификата через интернет.
5. Изучите Subject, Issuer, Thumbprint, срок действия, цепочку и статусы проверки.

Можно создать самоподписанный тестовый сертификат с помощью OpenSSL:

```bash
openssl req -x509 -newkey rsa:2048 -keyout test-key.pem -out test-cert.pem -days 30 -nodes -subj "/CN=Test Certificate"
```

Затем укажите `test-cert.pem`. Самоподписанный сертификат обычно не будет доверенным в системном хранилище, поэтому ожидаемый результат — ошибка `UntrustedRoot` или аналогичный статус.

### 4. RBAC и журнал

При первом запуске будет создан пользователь Administrator. После входа выберите `6`, чтобы добавить пользователей с ролями SecurityOperator или Auditor.

Для проверки разграничения прав:

1. Создайте пользователя с ролью Auditor.
2. Выйдите из программы и войдите под ним.
3. Проверьте, что аудитору доступны проверка сертификата и журнал, но недоступны BCrypt, DPAPI и управление пользователями.
4. Выберите `7`, чтобы просмотреть последние записи журнала.
